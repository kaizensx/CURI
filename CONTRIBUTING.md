# Contributing

Thanks for wanting to make CURI better. A few rules keep the project honest and safe.

## Before you open a PR
- `cd core && npm test` must pass. The end-to-end tests only run if Claude Code is installed, and they always use throwaway Claude profiles.
- Open the app (`node core/bin/curi.mjs app`) and look at the screens you changed, in dark and light, and at 960 px wide.
- No made-up data in the interface: metrics, states and progress come from the engine. With no data, show a clear empty state.
- Interface copy is short and actionable. Errors say what happened and what to do next.

## Sensitive areas (describe the risk in your PR)
- `core/src/policy.mjs`: the autonomy matrix. Moving a category to "automatic" needs a reason.
- `core/src/installers.mjs`, `core/src/handlers.mjs`: anything that writes outside CURI's data folder.
- `core/src/vault.mjs`, `core/src/connections.mjs`: credentials. Secrets never go in argv, logs, exports or API responses.
- `core/src/mcp.mjs`, `core/src/server.mjs`: surfaces exposed to Claude and to the interface.

## New integrations
A resource gets an install action only when the option is confirmed in its registry (npm, PyPI, crates.io, Homebrew, WinGet, Flathub) or reviewed by hand in `core/data/profiles.json`, with a pinned version where the method allows it, and a test that proves it ends up working, not just "installed".

## Brand
Assets are generated by `node brand/build.mjs` from a single geometry. Don't edit the PNGs by hand.
